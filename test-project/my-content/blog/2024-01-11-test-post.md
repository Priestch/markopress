# Testing MarkoPress with Custom Directories

Today we're testing MarkoPress with a custom content directory to demonstrate how flexible the configuration is.

## Why This Matters

When building documentation sites or blogs, you often have existing content in a specific structure. MarkoPress lets you specify exactly where your content lives, rather than forcing you to reorganize everything.

## The Test Setup

We created a test project with the following structure:

```
test-project/
└── my-content/
    ├── pages/
    ├── docs/
    └── blog/
```

## Configuration

In `markopress.config.ts`:

```typescript
export default defineConfig({
  content: {
    pages: 'my-content/pages',
    docs: 'my-content/docs',
    blog: 'my-content/blog',
  },
});
```

That's it! MarkoPress now reads from `my-content/` instead of the default `content/` directory.

## What Works

Everything works exactly the same:

- ✅ Pages render at `/`
- ✅ Docs with sidebar navigation
- ✅ Blog with RSS feeds
- ✅ Markdown processing
- ✅ Syntax highlighting
- ✅ Theme customization
- ✅ Plugin system
